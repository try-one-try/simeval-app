# SimEval 技术架构与 API 文档

| 项目 | 内容 |
|---|---|
| 架构形态 | Next.js 模块化单体；同一应用提供页面、服务端动作与 HTTP API |
| 运行环境 | Vercel 部署应用；Neon PostgreSQL 保存业务数据 |
| 接口基线 | OpenAPI 3.1，契约版本 0.6.0；14 项业务操作已实现，5 项保留为计划 |
| 产品边界 | 数据、质量检查和评测执行均为合成或模拟；不运行真实仿真器或模型训练 |

## 1. 系统结构

~~~mermaid
flowchart LR
  Browser[浏览器] --> Next[Next.js 页面与 API]
  Next --> Auth[Auth.js 会话与权限]
  Next --> App[应用服务]
  App --> Domain[领域规则]
  App --> Provider[模拟评测 Provider]
  App --> Repo[Prisma 仓储与事务]
  Repo --> DB[(Neon PostgreSQL)]
~~~

选择模块化单体，是为了让一次评测所需的身份、质量、任务、指标和复核在清楚的模块边界内协作，同时避免演示阶段引入消息队列、微服务或 WebSocket。页面只组织展示；业务规则由应用层和领域层处理；客户端不接触 Prisma 或服务端密钥。

依赖方向是“页面／HTTP 入口 → 应用服务 → 领域规则、Provider、仓储 → 数据库”。路由不直接写业务规则，页面不直接写数据库。新增评测引擎或 AI 服务时应替换相应 Provider，并在服务端校验输出；当前没有这类外部执行服务。

公开主页为独立展示模块：服务端输出内容，客户端把指针位置映射到 Canvas 序列帧。正文和链接集中于 `features/home/content.ts`，样式用 CSS Module 隔离；动作引擎负责图集下载、有限解码缓存、逐帧回程及卸载清理。主页没有新增业务 HTTP 接口；“开始体验”仍进入原登录流程。

## 2. 数据与关键流程

| 数据对象 | 职责与关系 |
|---|---|
| User、AccessAttempt | 预设演示身份；访问错误次数与封锁窗口。访问密码不写入数据库。 |
| Project、ModelVersion、DatasetVersion、Benchmark | 描述项目、可选版本、数据质量和评测口径。Benchmark 下的 MetricDefinition 定义指标单位与方向。 |
| EvaluationRun | 一次独立评测，保存配置快照、创建者、状态、可选基线及重试来源；软删除只隐藏普通入口。 |
| MetricResult | 按任务、指标与场景保存结果及样本数；结果与状态一起持久化。 |
| AnomalySample、ReviewRecord | 异常证据、草稿／最终结论、编辑版本，以及只追加的修改历史。 |
| AuditLog | 记录重要写入的操作者、对象、请求 ID 和时间。 |
| AIReport | 已有历史兼容与过时标记的数据结构；生成、读取和确认业务尚未开放。 |

创建评测时，服务端重新检查角色、配置兼容性、质量状态、基线和并发任务容量。新任务初始为 QUEUED。浏览器调用同步接口后，Mock 根据服务器时间将其推进到 RUNNING、SUCCEEDED 或 FAILED；读取接口本身不触发状态变化。当前实现没有后台 Worker，也不执行真实 Episode。Mock 使用配置快照、Seed 和 Episode 数生成可复现的合成指标。

重要状态写入使用数据库事务：任务完成时同时保存指标、异常、终态和审计；复核时同时保存当前结论、历史、审计和旧报告过时标记。创建／重试使用幂等键防重复；结论修改使用版本号防止并发覆盖。失败任务的重试产生新 ID，原任务保留。每位工程师最多有 3 个进行中任务。

## 3. 身份、安全与通用 HTTP 约定

- 登录、切换身份、退出由 Auth.js 与服务端动作完成；`/api/auth/[...nextauth]` 是框架路由，不计入下文 14 项业务接口。演示会话是最长 12 小时的 JWT Cookie；页面和 API 仍从数据库复查账号与角色。
- 框架路由 `GET/POST /api/auth/[...nextauth]` 由 Auth.js 处理会话、回调等认证请求；`/login` 是页面，身份切换使用服务端动作。它们不采用下文业务接口的 `data/meta` 契约。
- 所有业务接口需要有效 Session Cookie。POST、PATCH、DELETE 还要求同源 Origin；有请求体的操作要求 `Content-Type: application/json`。服务端以 Zod 校验输入，拒绝不认识的字段。
- ID 为 1–64 位字母、数字、下划线或连字符。分页从 1 开始，`pageSize` 默认 20、最多 100。`Idempotency-Key` 长 1–128 位，用于创建和重试；同用户同操作同键同内容返回已有对象，同键不同内容返回 409。
- 成功响应统一为 `{"data":...,"meta":{"requestId":"..."}}`；分页响应的 `meta` 另有 `page`、`pageSize`、`total`。错误响应为 `{"error":{"code":"...","message":"...","fieldErrors":null,"requestId":"..."}}`。返回值不包含数据库密码、SQL 或堆栈。
- ENGINEER 能管理本人任务；REVIEWER 能查看共享任务并确认最终结论。软删除任务从普通列表和详情隐藏，但已有引用保留。固定 Seed 任务不能被当作用户新建任务删除。

例如，状态查询成功时返回：

~~~json
{
  "data": {
    "runId": "run_example",
    "status": "RUNNING",
    "progress": null,
    "startedAt": "2026-09-26T10:00:01Z",
    "finishedAt": null,
    "pollAfterMs": 1500
  },
  "meta": { "requestId": "request_example" }
}
~~~

质量警告未确认时返回：

~~~json
{
  "error": {
    "code": "QUALITY_WARNING_NOT_ACCEPTED",
    "message": "请先确认数据集质量警告",
    "fieldErrors": { "acceptQualityWarning": ["必须明确接受质量警告"] },
    "requestId": "request_example"
  }
}
~~~

### 主要状态与错误

| 项目 | 值与含义 |
|---|---|
| 质量 | PASSED：可创建；WARNING：明确接受后可创建；FAILED：阻断。 |
| 任务 | QUEUED → RUNNING → SUCCEEDED／FAILED；未结束时可取消为 CANCELLED。运行中 `progress` 为 `null`，不伪造百分比。 |
| 异常 | OPEN、IN_REVIEW、RESOLVED、REOPENED；当前业务开放草稿和确认，不开放指派／重开接口。 |
| 401 UNAUTHENTICATED | 无有效会话或预设账号失效。 |
| 403 FORBIDDEN | 角色、归属或写请求 Origin 不满足。 |
| 404 NOT_FOUND | 对象不存在或被隐藏。 |
| 409 IDEMPOTENCY_CONFLICT／STATE_CONFLICT／TASK_LIMIT_REACHED／VERSION_CONFLICT | 幂等键内容不同、状态不允许、进行中任务已满、结论版本过期。 |
| 422 VALIDATION_ERROR／QUALITY_WARNING_NOT_ACCEPTED／DATASET_QUALITY_BLOCKED／INCOMPATIBLE_CONFIGURATION | 请求不合法、未接受警告、质量失败或配置／基线不兼容。 |
| 503 EXTERNAL_SERVICE_ERROR；500 INTERNAL_ERROR | Provider 无法完成模拟，或发生未预期服务错误。 |

## 4. 已实现的业务接口（14 项）

表中的“返回”指 `data` 的主要内容；每次响应还带 `meta.requestId`。除注明外，成功状态为 HTTP 200，所有请求都需登录。`{datasetId}`、`{runId}`、`{sampleId}` 是路径参数。

### 配置与质量

| 方法与路径 | 角色 | 请求 | 返回 |
|---|---|---|---|
| GET `/api/evaluation-catalog` | ENGINEER、REVIEWER | 无参数。 | `project`、`models`、`datasets`（含质量摘要）、`benchmarks`（含兼容范围与 Episode 上下限）、`baselines`、`recent`、`activeTaskLimit=3`。 |
| GET `/api/datasets/{datasetId}/quality` | ENGINEER、REVIEWER | 路径 `datasetId`。 | `dataset`（名称、版本、样本数、质量状态）、`checks[]`（检查名、状态、受影响数、说明）、`canStartEvaluation`。 |

### 评测任务

| 方法与路径 | 角色 | 请求 | 返回与关键规则 |
|---|---|---|---|
| GET `/api/evaluation-runs` | ENGINEER、REVIEWER | 可选 `page`、`pageSize`、`status`、`projectId`。 | `Run[]`，分页元数据；过滤软删除，按创建时间和 ID 倒序。 |
| POST `/api/evaluation-runs` | ENGINEER | 必须带 `Idempotency-Key`；JSON 字段见下方“创建请求”。 | `Run`；首次 201，同内容重复 200。新任务为 QUEUED；警告未接受或质量失败时拒绝。 |
| GET `/api/evaluation-runs/{runId}` | ENGINEER、REVIEWER | 路径 `runId`。 | `Run`，含配置、当前状态、指标摘要与异常数量；未完成时不伪造结果。 |
| GET `/api/evaluation-runs/{runId}/status` | ENGINEER、REVIEWER | 路径 `runId`。 | `runId`、`status`、`progress`、`startedAt`、`finishedAt`、`pollAfterMs`；只读。 |
| POST `/api/evaluation-runs/{runId}/sync` | ENGINEER、REVIEWER | 路径 `runId`；无请求体。 | 与状态接口同形状；按服务器时间推进模拟，重复调用不重复写结果。 |
| POST `/api/evaluation-runs/{runId}/cancel` | ENGINEER | 本人任务，路径 `runId`；无请求体。 | `Run`；仅 QUEUED／RUNNING 可取消，完成竞争时返回最新结果或 409。 |
| POST `/api/evaluation-runs/{runId}/retry` | ENGINEER | 本人 FAILED 任务；`Idempotency-Key`；无请求体。 | 新 `Run`，`retryOfRunId` 指向原任务；首次 201，重复 200。重新检查配置和质量。 |
| DELETE `/api/evaluation-runs/{runId}` | ENGINEER | 本人终态任务；无请求体。 | `runId`、`deletedAt`；软删除，重复请求仍返回 200。进行中须先取消，固定示例受保护。 |

**创建请求 JSON**：必填 `name`（去空格后 1–120 字）、`modelVersionId`、`datasetVersionId`、`benchmarkId`、`episodeCount`（1–10000，且满足所选 Benchmark 更窄的范围）、`simulationSeed`（0–2147483647）、`acceptQualityWarning`（布尔值）。可选 `baselineRunId`（可为 `null`）、`targetSuccessRate`（`0.8`、`0.85` 或 `null`）、`mockFailure`（故障演示，默认 `false`）。基线必须成功且同项目、同数据、同 Benchmark、同 Episode／Seed，模型版本不同；成功率目标不影响模拟结果。

`Run` 至少包含：ID／名称、项目／模型／数据／Benchmark ID 与显示名称、创建者、`status`、`baselineRunId`、`retryOfRunId`、Episode／Seed、`provider`、创建／开始／结束时间、错误代码／说明、`isDemoFixture`、`targetSuccessRate`、`anomalyCount`、`pendingReviewCount`、`successRule` 和 `metrics[]`。每项指标给出键、名称、单位、场景、值和样本数。

### 对比与异常复核

| 方法与路径 | 角色 | 请求 | 返回与关键规则 |
|---|---|---|---|
| GET `/api/comparisons` | ENGINEER | 必填 `candidateRunId`；可选 `baselineRunId`、`scenarioKey`。 | `candidate`、可空 `baseline`、可选基线、`metrics[]`、异常数与待复核数。没有基线时仅显示当前结果；不兼容数据不计算差值。 |
| GET `/api/anomaly-samples` | ENGINEER、REVIEWER | 必填 `runId`；可选 `metricKey`、`scenarioKey`、`status`、`reviewState=pending/confirmed`、`page`、`pageSize`。 | `Sample[]` 与分页元数据；只能查已完成且可见的任务。 |
| GET `/api/anomaly-samples/{sampleId}` | ENGINEER、REVIEWER | 路径 `sampleId`；可选 `runId` 校验父任务。 | `sample`、`run`、`history[]`、`staleReportCount`；包含日志、草稿、最终结论和版本。 |
| PATCH `/api/anomaly-samples/{sampleId}/review` | ENGINEER、REVIEWER | JSON：`conclusion`、`mode`、`expectedVersion`。 | 更新后的样本详情。工程师仅能为本人任务保存 `draft`；评测人员可 `draft` 或 `confirm`。版本不一致返回 409。 |

**复核请求字段**：`conclusion` 为去空格后 1–4000 字的自由文本；`mode` 只能为 `draft` 或 `confirm`；`expectedVersion` 是刚读取的样本版本，最小为 1。成功保存会增加 `sample.version` 并追加历史；最终文字改变才增加 `confirmedRevision`。历史记录含模式、内容、操作者、时间、前后版本及确认修订号。

**对比指标口径**：每项给出 `candidateValue`、可空 `baselineValue`、双方样本数、`delta`、`deltaUnit`、方向、判断（IMPROVEMENT／REGRESSION／UNCHANGED／NOT_COMPARABLE／CURRENT_ONLY）、原因和证据数。总体场景键为 `__overall__`；百分比之差用百分点 `pp`。缺值或不兼容时 `delta=null`，不把缺失当成零。

## 5. 已定义但未实现的接口（5 项）

以下是设计契约，当前没有对应的可调用业务路由；调用不能得到表中的目标结果。列出它们是为了明确后续边界。

| 计划方法与路径 | 角色 | 计划请求 | 计划返回 |
|---|---|---|---|
| PATCH `/api/anomaly-samples/{sampleId}/assignment` | ENGINEER、REVIEWER | `assigneeId`、`expectedVersion`。 | 更新后的样本详情。 |
| POST `/api/anomaly-samples/{sampleId}/reopen` | REVIEWER | `reason`（1–500 字）、`expectedVersion`。 | 重开后的样本与历史。 |
| POST `/api/ai-reports` | ENGINEER、REVIEWER | `Idempotency-Key`；`runId` 必填，`baselineRunId` 可选。 | 首次 201 的 READY 报告草稿；重复 200。 |
| GET `/api/ai-reports/{reportId}` | ENGINEER、REVIEWER | 路径 `reportId`。 | 报告内容、指标／样本引用、来源版本和过时状态。 |
| POST `/api/ai-reports/{reportId}/confirm` | REVIEWER | 路径 `reportId`；无请求体。 | 已确认报告。 |

计划报告会保存 `summary`、`findings[]`、`evidenceSampleIds[]`、`provider`、`sourceReviewVersions`、`isStale`、确认人与确认时间。当前仅保留相关数据结构和旧报告过时标记；生成、读取和确认流程未交付。

## 6. 调用示例

以下占位符代表当前站点与当前浏览器会话，不包含真实口令或 Cookie。写操作的 Origin 必须与站点一致。

~~~http
GET /api/evaluation-catalog
Cookie: <当前会话 Cookie>

POST /api/evaluation-runs
Cookie: <当前会话 Cookie>
Origin: <当前站点 Origin>
Content-Type: application/json
Idempotency-Key: evaluation-demo-001

{
  "name": "Warehouse Manipulation Evaluation v2.4",
  "modelVersionId": "demo-model-candidate",
  "datasetVersionId": "demo-dataset-scenes-v3",
  "benchmarkId": "demo-benchmark-v1",
  "baselineRunId": null,
  "targetSuccessRate": 0.8,
  "episodeCount": 200,
  "simulationSeed": 20260901,
  "acceptQualityWarning": true,
  "mockFailure": false
}
~~~

首次创建返回 HTTP 201，`data.id` 为新任务 ID；用同一键与相同内容重发返回 HTTP 200 的原任务。随后读取 `GET /api/evaluation-runs/{runId}/status`，并在需要推进演示时调用 `POST /api/evaluation-runs/{runId}/sync`。模拟结果完成后，可读取对比和异常，再用当前样本的 `version` 提交复核：

~~~http
PATCH /api/anomaly-samples/{sampleId}/review
Cookie: <当前会话 Cookie>
Origin: <当前站点 Origin>
Content-Type: application/json

{"conclusion":"日志显示遮挡区域发生碰撞，建议调整路径并复测。","mode":"draft","expectedVersion":1}
~~~

工程师保存草稿，评测人员可改为 `"mode":"confirm"` 确认最终结论。提交前如果别人已保存新版本，服务端返回 409；客户端应保留用户输入、重新读取并人工核对。

## 7. 部署、数据恢复与验证边界

`DATABASE_URL` 用于网页池化连接；`DIRECT_URL` 或 `DATABASE_URL_UNPOOLED` 用于迁移、Seed 和维护；`AUTH_SECRET` 与 `ACCESS_PASSWORD` 只在服务端使用，真实值不提交 Git。开发、集成测试和生产使用不同的 PostgreSQL 数据库或 Neon 分支。普通构建与发布不自动执行 Seed、迁移或数据重置；恢复演示数据由独立脚本显式发起。

代码通过 lint、类型检查、单元测试、独立 PostgreSQL 集成测试和构建检查；页面仍需实际走查登录、两角色、质量门禁、任务管理、比较、复核、窄屏以及错误／空状态。网站可访问不等于各地网络表现一致，合成指标也不等于真实仿真结果。
