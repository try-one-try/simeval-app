# SimEval 产品需求文档（PRD）

| 项目 | 内容 |
|---|---|
| 产品定位 | 面向具身智能团队的评测数据工作台 |
| 文档范围 | 当前产品目标、已实现的业务能力及明确的后续范围 |
| 产品状态 | 质量、模拟评测、对比和异常复核已实现；AI 报告闭环未实现 |

## 1. 背景与目标

模型版本迭代不能只看一个总体分数。团队还需要知道评测采用了什么数据与规则、数据本身是否可靠、哪些场景改善或回退、异常证据是什么，以及最终结论由谁确认。SimEval 将这些问题串成一条可追溯的工作流程：**配置评测 → 确认质量 → 模拟执行 → 查看与比较结果 → 复核异常 → 形成报告**。其中报告环节是后续目标，当前可用流程止于人工复核。

本产品基于岗位和领域分析设计，尚无真实用户调研。当前数据、质量报告、执行过程和指标均为合成演示；目标是验证工作流与工程边界，不宣称真实模型性能或业务收益。

## 2. 用户与权限

| 角色 | 要完成的工作 | 权限边界 |
|---|---|---|
| 算法工程师（ENGINEER） | 配置评测、管理本人任务、查看模型对比、定位异常、保存复核草稿。 | 可创建、取消、重试和软删除本人任务；不能确认最终结论。 |
| 评测人员（REVIEWER） | 查看共享任务与异常证据，编辑并确认最终结论。 | 不能创建、取消、重试或删除任务，也不能进入工程师专属的模型对比操作。 |

访客输入共享访问密码并选择演示身份，不提供注册。身份切换会建立对应的服务端会话；服务端每次仍检查角色与对象权限。共享密码控制访问范围，但不能证明访客的真实身份。

公开主页先介绍产品与开发过程：左侧可直达 PRD、架构接口、Figma 和开发流程；右侧介绍当前可用的评测与复核路径，“开始体验”进入访问密码页。中央人物支持鼠标四向动作、触屏按钮和键盘操作；完整动作素材就绪后展示，加载失败可重试或主动切换静态浏览。主页不访问业务数据库，也不绕过工作区门禁。

## 3. 核心场景与功能需求

下表的“已实现”表示当前代码和业务接口可用；“计划中”表示产品目标，不能当作已交付功能演示。

| 编号 | 能力与用户操作 | 关键规则与完成标准 | 状态 |
|---|---|---|---|
| FR-01 | 访问与切换身份 | 未登录者不能直接进入工作台或调用业务接口；两种身份有不同入口和操作权限；已授权者切换身份无需重输密码。 | 已实现 |
| FR-02 | 配置评测 | 填写任务名，选择模型版本、数据集、Benchmark、Episode 数和模拟 Seed；比较基线与总体成功率目标可选。组合不兼容时解释原因。 | 已实现 |
| FR-03 | 数据质量确认 | 预置检查结果为 PASSED 时可继续；WARNING 必须明确接受；FAILED 阻断。更换数据集后重新确认，服务端在创建时再检查。 | 已实现 |
| FR-04 | 创建与模拟执行 | 提交后才生成独立任务；从 QUEUED 到 RUNNING，再到 SUCCEEDED／FAILED，也可在未结束时取消。状态与结果持久化；没有基线也能创建。 | 已实现 |
| FR-05 | 多任务管理 | 明确选择当前任务，切换板块仍带同一个任务 ID；本人可取消进行中任务、为失败任务创建新 ID 重试、软删除终态任务。固定演示任务受保护。 | 已实现 |
| FR-06 | 结果与模型对比 | 显示指标值、单位、方向和样本数；只比较同项目、同数据、同 Benchmark、同 Episode／Seed 且模型版本不同的成功任务。没有基线时只看当前结果。 | 已实现 |
| FR-07 | 异常样本复核 | 从结果进入证据、日志和历史；工程师保存草稿，评测人员确认或修改最终结论。并发编辑不能覆盖他人内容，修改保留操作者和时间。 | 已实现 |
| FR-08 | AI 报告与人工确认 | 预期只引用有效指标和样本证据，先形成草稿，再由评测人员确认；结论变化后旧报告应标为过时。 | 计划中；生成与确认未实现 |

## 4. 主要交互与状态口径

- **导航**：创建评测、评测任务、模型对比、异常复核、报告、总览按工作目的组织。除创建外，从顶层入口进入先选任务；流程中的下一步沿用当前任务。
- **空、错与权限状态**：没有任务、没有基线、未完成、无异常、网络失败、无权限都给明确提示和可行的下一步；不能把未完成任务显示成已有结果。
- **质量与结果是两回事**：数据集质量通过不意味着模型达标；模拟成功也不意味着达到业务目标。总体成功率目标用于判断是否达标，不参与指标计算；历史基线用于比较版本变化。
- **任务管理**：每位工程师最多同时有 3 个 QUEUED／RUNNING 任务；终态释放名额。重试保留原任务，软删除仅隐藏普通入口，保留历史引用和审计。
- **复核**：草稿与最终结论分开；每次保存增加编辑版本。最终结论变化时，引用旧版本的报告记录应标记过时，但当前尚未开放报告生成／确认。
- **演示真实性**：数据集统计、模拟 Episode 数、指标样本数和异常记录数分别标注，不混写成真实导入量或真实运行次数。运行中不编造进度百分比。

## 5. 典型演示故事

固定仓储场景使用合成数据：候选模型的总体成功率从 **76% 到 81%**，但遮挡场景碰撞率从 **8% 到 13%**。用户先确认总体改善，再沿着场景指标进入异常样本，阅读日志并写下需要人工确认的结论。这个故事用于展示“总体改善不等于所有场景改善”；数字不是生产环境实测。

## 6. 范围与验收

**当前范围**：预设身份与访问控制、自主配置、预置质量门禁、确定性模拟、任务持久化与管理、同口径对比、异常证据与人工结论、必要的审计及错误反馈。**后续阶段**：主页导览和 AI 报告闭环。**不在当前 MVP 范围**：真实仿真或训练、实时数据扫描／ETL、独立回补任务、人工分类步骤、大文件上传、批量复核、通知、计费和多租户。

验收按可观察行为判断：错误质量状态不能绕过服务端；首次无基线评测可成功；任务之间不混用结果和结论；取消、重试、删除遵守归属和状态；同口径比较拒绝不兼容任务；草稿、确认、修改历史及并发冲突可复现；刷新后保存的数据仍在。线上可达性、首访耗时和 AI 报告完成度单独验收，不以设计稿或数据库表存在代替功能交付。

## 7. 非功能要求

| 方面 | 验收要求 |
|---|---|
| 安全 | 密钥只留在服务端；所有写入检查会话、角色、参数、归属和状态；连续输错访问密码需要限制。 |
| 数据一致性 | 任务结果、结论历史与审计持久化；重复提交不重复建任务，并发编辑不静默覆盖。 |
| 可用性 | 加载、空数据、错误、无权限和成功状态都有反馈；窄屏与键盘操作可用。 |
| 演示可信度 | 合成内容显著标注；没有真实测量的数据不写成性能提升或业务收益，首访时间需实测后再报告。 |
