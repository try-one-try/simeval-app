# SimEval 产品需求文档（PRD）

SimEval 是面向具身智能团队的评测数据工作台。它把评测配置、数据质量、结果比较、异常证据和人工结论放进同一条流程，帮助用户说明一次评测的结果是怎样得到的，以及哪些判断仍需确认。

本文定义当前产品的完整范围和验收要求。需求来自对具身智能评测工作的领域分析，尚未经过真实用户调研。演示中的数据、质量检查和评测结果均为合成内容，执行过程为模拟；聊天助手使用真实模型分析这些资料，正式报告由系统模板整理。文档不以演示分数证明真实模型能力或业务收益。

## 1. 背景与问题

以仓储抓取和放置为例，一个模型版本可能提高了总体成功率，却在遮挡场景中更容易发生碰撞。如果只展示总体分数，用户很难判断改善发生在哪里，也难以找到需要复核的样本。

评测条件同样影响判断。比较不同模型版本时，如果数据集版本、测试场景、执行次数或模拟参数也发生变化，两组数字就未必适合直接比较；数据存在缺失或标注问题时，结果还需要附带质量前提。指标只能说明表现，日志中的现象和人工确认的原因也应分别记录。

SimEval 因此需要解决三个相连的问题：评测前说明条件和数据风险，评测后从指标找到异常证据，最后保留谁确认了什么结论。聊天助手帮助查找和理解资料，人工复核与报告确认保留明确的责任边界。

## 2. 产品目标与范围

产品目标是让用户完成一次可追溯的评测。完成流程后，用户应能回答：测了哪个模型、用了什么数据与规则、结果是否达到设定目标、与历史版本相比哪里变化、异常依据是什么，以及结论是否经过人工确认。

当前范围包含共享密码访问、两种演示身份、评测配置、预置质量检查、模拟执行、多任务管理、结果查看、模型对比、异常复核、聊天调查和系统报告。公开主页介绍产品、设计与开发资料，并提供工作台入口。

当前版本不包含真实仿真器、模型训练、实时数据扫描或 ETL（数据抽取、转换与入库）、大文件上传、独立回补任务、人工分类步骤、批量复核、指派、通知、计费和多租户管理。任务信息集中在结果页，独立总览已取消。聊天采用一个 Agent，即一个根据问题选择查询工具并组织回答的助手；本版不提供多 Agent 协作、长期记忆或无人值守任务。

## 3. 用户、权限与访问

产品提供算法工程师和评测人员两种演示身份，无注册流程。访客输入共享访问密码并选择身份后进入工作台；已获准访问的访客可在右上角切换身份或退出。切换身份会建立对应的服务端会话，不能仅通过改变页面上的角色名称获得权限。

| 身份 | 主要工作 | 操作边界 |
|---|---|---|
| 算法工程师（ENGINEER） | 配置评测、查看和比较结果、调查异常、编写草稿 | 可创建任务，管理本人任务，编辑本人任务的复核草稿；可生成、更新和阅读报告，不能确认最终结论或报告。 |
| 评测人员（REVIEWER） | 阅读共享任务与证据、复核结论、确认报告 | 可编辑共享草稿、确认或修改最终结论，生成、更新和确认报告；不能创建或管理评测任务，也不能使用模型对比及助手的比较工具。 |

两种身份都能阅读共享任务、异常和报告。共享密码控制访问范围，演示身份并不证明访客的真实身份；不同访客的业务操作会影响同一份共享数据。私人聊天则按每次登录隔离，具体规则见第 5.6 节。

工程师登录后默认进入创建评测，评测人员默认进入异常复核的任务选择页。页面和接口都必须检查登录状态与权限，隐藏按钮不能代替服务端校验。未登录直访工作台需回到登录页，无权限操作应说明原因。

## 4. 一次评测的完整流程

黄金路径是产品必须完整支持的主要使用流程：

1. **配置评测。** 工程师填写任务名称，选择模型、数据集和评测规则；可设置成功率目标，也可选择一份成功的历史任务作为比较基线。
2. **确认数据质量。** 查看所选数据集的预置检查。质量警告必须明确接受，质量失败则返回修改配置。
3. **创建并执行。** 提交后生成独立任务，查看等待、执行和结束状态；必要时取消，失败后可创建重试任务。
4. **理解结果。** 查看当前指标与是否达标；需要版本比较时，由工程师选择兼容的历史任务。
5. **定位并复核异常。** 从指标进入相关样本，阅读日志，编写草稿，再由评测人员确认或修改最终结论。
6. **按需使用助手。** 围绕当前任务提问，查看回答的证据和实际查询记录，再返回原页面核对或操作。
7. **形成报告。** 系统整理当前任务的指标和人工结论；来源发生变化时更新同一份报告，由评测人员核对后确认。

比较和聊天均为可选步骤。没有历史基线的首次评测仍能完成执行、复核和报告流程；生成报告也不需要先与助手聊天。

从顶层导航进入评测任务、模型对比、异常复核或报告时，用户先选择任务。进入后持续显示任务名称和编号，正文中的返回与继续操作沿用同一个任务，并保留已选基线和异常筛选条件。返回样本列表时恢复原筛选，避免用户把不同任务的证据或结论混在一起。旧总览地址跳转到对应任务结果，无法确定任务时回到任务列表。

## 5. 功能规则

### 5.1 配置评测

创建分为“配置评测”和“确认数据质量”两步。进入时不替用户选择模型、数据集或评测规则；“使用演示配置”仅填入可修改的内容，仍需用户确认质量并提交。提交前不产生任务。

配置中几个概念各有用途：

- **Benchmark（评测基准）**定义测试场景、指标和一次尝试的成功规则，例如是否在规定时间内完成抓取和放置。
- **Episode**表示一次完整的任务尝试。数量必须是整数，并符合所选数据集与评测基准的范围。
- **Seed（模拟随机种子）**用于复现模拟结果。相同模型、数据集、评测基准、Episode 数量和 Seed 应得到相同指标。
- **达标目标**用于判断本次总体成功率是否达到要求，可不设置，也可选择 80% 或 85%。它不参与指标计算。
- **历史基线**是用于比较的另一份成功评测结果，可不选择。基线也不参与本次结果计算。

模型、数据集和评测基准必须属于同一项目并彼此兼容。配置页说明成功规则与可用范围，不兼容时指出要修改的字段。创建时服务端重新检查这些条件。

任务名称去除两端空格后为 1–120 字。同项目中所有未删除任务的名称均占用名称，包括固定示例和其他创建者的任务；判重忽略英文字母大小写。点击“检查数据质量”时即检查名称，重名则保留全部输入、停留在配置步骤并定位名称字段。点击“使用演示配置”会按最新任务记录避开重名，优先使用模板原名，已占用时加上 `(2)`、`(3)` 等空闲编号；用户仍可手工修改。填表和检查不预留名称，最终创建时再次查重。已删除任务的名称可再次使用。

运行参数中提供明确标注的“模拟执行失败”选项，用于体验失败与重试流程。它不表示模型在真实环境中发生了故障。

### 5.2 确认数据质量

质量页展示数据库中已有的检查报告，注明“合成数据、预置检查、非实时扫描”。检查项目应说明发现的问题和影响范围，让用户知道继续评测所接受的前提。

三种质量状态对应不同动作：

- **通过（PASSED）**：允许创建评测。
- **警告（WARNING）**：说明风险，用户明确勾选接受后才允许创建。
- **失败（FAILED）**：阻止创建，提示返回选择可用数据。

返回修改配置或更换数据集后，旧质量确认不再沿用；再次提交前需读取并确认当前数据质量。服务端必须重新检查质量状态和警告接受情况，不能依赖页面按钮是否可点。

数据集样本量、质量问题影响数量、模拟 Episode 数、指标样本数和异常记录数分别展示。它们描述不同对象，不能把质量警告数量当作本次执行的异常数量。质量通过只说明数据允许进入评测，模型是否达标需在拿到结果后判断。

### 5.3 执行与任务管理

提交成功后，系统保存任务编号、创建者、配置和质量接受记录，并进入任务结果页。模拟计算使用创建时保存的配置，模型、数据、评测基准、Episode 和 Seed 都参与结果口径；不能让所有配置返回同一组成绩。

任务先为等待执行（QUEUED），再进入执行中（RUNNING），最后变为已完成（SUCCEEDED）或执行失败（FAILED）。结束前可以取消为 CANCELLED。已完成表示指标和异常记录已保存，是否达到目标另行判断；失败和取消的任务不展示本次成功结果。

页面自动同步状态，等待和执行期间展示活动提示及已用时间。进度条不表示完成比例。当前执行由页面同步请求推进模拟，不承诺真实仿真执行或离开页面后的后台持续运行；返回页面后读取已保存状态并继续同步。同步失败时停止动态提示，提供重新连接入口。

每位工程师最多同时有 3 个等待或执行中的任务，任务结束或取消后释放名额。多个任务分别保存状态、指标和证据；用户明确选择任务，系统不以最近一次任务替换当前对象。列表区分固定示例与用户新建任务，提供分页、总数和更换任务入口。

任务管理遵守以下规则：

- **取消**：仅工程师可取消本人等待或执行中的非固定任务，操作前需确认。若任务已经完成，拒绝取消并保留结果。
- **重试**：仅本人失败的非固定任务可重试。系统保留原失败记录，重新检查配置和质量，创建关联原记录的新任务编号；显式失败演示选项不带入重试。若无法沿用有效的质量确认，提示重新配置并确认。
- **重试命名**：使用“原名 · 重试 N”，从 1 起选择未被占用的编号；必要时截短原名，保证总长不超过 120 字。再次重试仍以直接来源任务的名称为基础。
- **删除**：仅本人已完成、失败或取消的非固定任务可软删除，即从普通入口隐藏记录，保留历史数据和引用。进行中的任务需先取消；删除后清除当前页面选择，不能继续复核或生成报告。原任务已经引用的隐藏基线可继续用于该任务的比较，隐藏任务不作为新的任意基线候选。

固定示例任务受到保护，不能取消、重试或删除。相同提交的网络重发不能重复创建任务或消耗额外名额；重发重试请求也应返回此前创建的任务编号和名称。

### 5.4 结果与模型对比

结果页集中展示状态、配置、成功规则、指标、目标判断、历史基线和待复核数量。指标应说明数值、单位、适用场景、样本数及改善方向；成功率越高越好，碰撞率、平均耗时和人工干预率越低越好。达到总体成功率目标后，仍需查看场景风险与异常证据，系统不自动形成模型发布决定。

模型对比仅对工程师开放。可比较的两个任务必须都成功，并且属于同一项目，采用同一数据集版本、评测基准版本、Episode 数量和 Seed，模型版本则必须不同。对比页只提供兼容的候选基线；更换基线只改变当前查看，不修改任务创建时的配置。没有兼容基线时说明“暂无同口径历史基线”，仍可查看当前指标。

每项指标按指标标识和场景配对。两侧单位、方向或样本数不同，或一侧缺少指标时，显示不可比较及原因，不生成差值或改善判断。可比较时，差值按“当前任务减历史基线”计算，再结合指标方向判断改善或回退。百分比指标的差值使用百分点，例如 76% 到 81% 是增加 5 个百分点。

首屏突出主要差异，完整指标可按需展开。从相关指标进入异常样本时携带场景和指标筛选。固定合成故事中，总体成功率由 76% 升至 81%，遮挡场景碰撞率却由 8% 升至 13%；它用于展示如何调查局部回退，这些数值不代表真实模型性能，也不能直接证明回退原因。

### 5.5 异常证据与人工复核

两种身份都能查看成功且未软删除任务的异常。列表支持场景、指标和复核状态筛选，显示分页和复核数量。详情说明样本属于哪个任务、日志来自何处，提供日志、已有草稿、最终结论和修改历史。合成日志或演示媒体必须说明来源。

异常列表与样本详情中的待复核状态可进入结论编辑区域，详情提供明确的“编辑／复核结论”按钮。任务选择页的红字仅提示复核状态；结果页和对比页通过原有异常入口继续调查，避免增加重复入口。

结论采用自由文本，去除两端空格后为 1–4000 字。工程师只可保存本人任务的草稿；评测人员可编辑共享草稿，并确认或修改最终结论。演示填充按钮只填入可修改的示例，不自动保存，也不把日志中的现象写成已经证实的原因。

草稿和最终结论分别保存。新草稿保留原已确认结论，同时将样本标为需要评测人员再次复核；确认后清除草稿，记录确认人、时间和历史。每次保存都增加编辑版本，最终文本发生变化时增加确认修订号。

保存时核对用户开始编辑时的版本。若另一位访客已更新结论，拒绝覆盖并保留当前输入，提示读取最新内容后重新核对。任务已隐藏或状态不允许时，同样拒绝写入。修改历史和审计记录随结论保存；审计记录说明谁在何时执行了什么操作，便于后续追溯。

### 5.6 评测聊天助手

登录后，工作台右下角提供常驻助手按钮，展开后可提问、查看历史、证据卡和实际查询记录。公开主页和登录页不显示助手。展开面板、切页和点击快捷问题只准备界面或预填文字，用户发送后才调用模型。

一个会话绑定一个成功且可见的任务，以及一个明确选择或未选择的基线。结果页提供当前任务，比较页提供已选基线，样本详情提供当前样本。没有明确任务时先选择，不能自动取最近任务。切到另一任务或基线时，保留原会话并提示是否开启针对本页的新对话，不能悄悄改变旧对话的分析对象。

助手根据问题选择四类只读工具：读取评测概况、比较指标、筛选异常、读取样本证据。服务器限定任务与样本归属，比较工具沿用工程师权限和同口径规则。助手可以说明线索、推测和建议；更改任务、保存结论及确认报告仍由用户在对应页面操作。

回答应区分已知事实与推测，并给出支持证据和仍待确认的事项。证据卡保留查询时的数据、时间和站内链接，实际工具记录显示查了什么、是否成功及结果摘要。系统核对引用确实来自本轮授权查询，但引用存在并不保证每句 AI 解释正确；用户仍需打开证据核查。查询失败不得伪装成“没有异常”，模型内部思考不作为工具记录展示。

业务来源变化后，旧回答标为历史结果并提示重新分析，原证据快照仍保留。聊天历史持久化，每轮只使用最近三轮成功问答作为近期背景。成功回答最多提供三条继续询问建议，点击只填入输入框，由用户修改并发送。

共享角色账号可能由多人使用，因此聊天同时绑定账号和本次登录标识。同一次有效登录内切页或刷新可恢复自己的已保存聊天；另一个浏览器、退出后重登或身份切换不能读取上一登录的私人对话。业务任务、复核和报告仍共享，聊天隔离不复制业务数据。

一轮调查可为运行中、成功、失败、中止或超时。同次登录最多一轮进行中，每个会话最多 16 轮，每次登录每小时最多 12 轮；同时受服务端整体并发、上下文和费用额度限制。达到限制时说明原因与可行操作。收起面板时当前页面中的调查可继续；停止会中止本轮并尽力取消模型请求，晚到的回答不能覆盖中止状态。刷新恢复保存内容，关闭页面后不保证继续执行尚未完成的调查。

### 5.7 系统评测报告

报告页为每个成功且可见的任务维护一份当前报告。工程师和评测人员都可生成、更新和阅读，只有评测人员可以确认。

报告由固定模板整理当前任务概况、指标、异常样本的人工确认结论和适用限制，不调用模型，也不读取私人聊天或加入历史基线的比较分析。最多展示 50 条样本，并说明完整待复核数量；缺少人工确认结论的样本明确标注。即使还有待复核样本，报告也应如实展示，由评测人员核对后确认。

来源未变化时，再次生成复用原报告编号、正文及确认状态。来源变化时，更新同一编号的报告，清除原确认人和时间，恢复待确认；更新前的正文、来源及确认信息进入审计。界面只展示当前报告，不堆积相同内容的报告版本。

系统保存生成报告时的来源版本，并在读取和确认时与当前数据核对。指标、样本状态或编辑版本变化均可能使报告过时，包括草稿的保存；报告正文仍只引用人工确认结论。来源过时后禁止确认，需更新并重新阅读。若其他访客已更新报告，旧页面也不能直接确认新正文。报告确认表示评测人员已核对这份报告，系统不据此自动决定模型发布。

### 5.8 公开主页

主页在访问工作台前介绍产品用途、完整流程、合成演示边界，并提供 PRD、架构接口、Figma 原型、源码和开发流程入口。“开始体验”进入访问密码页。

中央人物支持鼠标四向探索、在人物区域单指拖动和键盘操作。动作素材完整加载后展示；加载中有反馈，失败后可重试，也可选择静态浏览。主页不读取业务数据库，人物交互和资料阅读不改变工作台访问权限。

## 6. 状态与反馈要求

加载、空数据、错误、无权限和成功都属于功能本身。反馈需回答当前发生了什么、是否已保存以及接下来可以做什么。

| 情况 | 应有反馈 |
|---|---|
| 正在读取或提交 | 显示具体动作，提交期间防止重复点击；未完成任务不展示成功结果。 |
| 没有任务、基线、异常或报告 | 说明是哪类内容为空；工程师可创建任务，无基线可独立查看结果，无异常可继续报告，未生成报告可发起生成。 |
| 字段不合法或配置不兼容 | 标明需要修改的字段，保留已输入内容。 |
| 网络或服务读取失败 | 明确说明读取失败并提供重试，不能显示为有效空结果；状态同步可重新连接。 |
| 未登录或无权限 | 引导登录或说明当前角色限制，服务端拒绝越权请求。 |
| 结论版本冲突或报告来源更新 | 保留当前输入或阅读上下文，要求读取最新内容并核对，不能静默覆盖或确认。 |
| 操作成功 | 显示保存、创建、取消或确认后的状态，并能在刷新后读取。 |
| 助手失败、停止、超时或额度不足 | 显示该轮实际状态和原因，允许按情况重新提问、缩小范围或稍后再试。 |

红色复核提示须同时有文字说明，不依靠颜色传达状态。取消、删除、身份切换和结论保存都需要明确的结果反馈。

## 7. 非功能要求

**访问安全。** 密钥与模型调用留在服务端。每次写操作检查会话、角色、对象归属、参数和业务状态；连续输入错误访问密码需要限制。助手不能绕过原业务权限，也不能读取其他登录的私人聊天。

**数据一致性。** 任务状态、指标、异常、结论、报告和审计需持久化。重复请求复用已完成的同一次操作；多人同时操作时不能产生重复任务、重复报告或静默覆盖结论。完成、取消、删除、复核和报告确认发生竞争时，保存结果必须符合当前状态与来源。

**可用性。** 桌面和窄屏均能完成主要流程。导航、身份选择、弹层、人物和助手入口可通过键盘操作，弹层关闭后焦点返回触发位置；移动端面板适应键盘与安全区，浮动助手不遮挡主要操作。动画遵循减少动态效果设置。

**可追溯性。** 结果能够关联创建时的配置，结论能查到操作者与修改历史，聊天能打开查询时的证据，报告能核对来源和确认状态。合成、模拟、实时模型回答和历史回答均需如实标注。

**资源控制。** 列表分页读取，助手只获取必要范围的数据，并限制模型次数、查询次数、上下文、时长、频率、并发和累计费用。达到上限时返回可理解的错误，不无限运行。性能和使用效果需以实际测量为依据，本文不设未经测量的速度或收益承诺。

## 8. 可观察的验收标准

验收围绕用户实际可见的行为进行：

1. 未登录不能进入工作台或调用业务接口；两种身份的导航、页面和写操作符合权限表，身份切换后权限随会话改变。
2. 工程师能自主填写配置；无基线仍可创建。错误组合、超范围参数和重名均阻止提交并保留输入，大小写与两端空格不能绕过名称判重。
3. 质量通过可继续，警告未接受不能创建，失败始终阻断；更换配置后旧确认失效，直接提交接口也无法绕过检查。
4. 任务状态能从等待到结束，刷新可读到已保存结果；相同配置与 Seed 复现相同指标，执行失败和取消不冒充成功，状态同步失败可恢复。
5. 多任务切换后指标、样本、基线和结论保持归属；本人取消、失败重试和终态删除遵守规则，固定示例受保护。重复提交返回原任务，重试另建编号并自动避开重名。
6. 比较只接受兼容成功任务；缺少指标或样本数不一致时显示不可比，百分比差值使用百分点。指标下钻与返回保留任务、基线和筛选。
7. 工程师草稿不覆盖已有确认，评测人员可确认和修改；刷新可读到结论与历史。同时编辑触发冲突时保留输入，隐藏任务不能继续写入。
8. 助手发送后才调用模型，展示实际工具记录和可打开的证据；越权样本和评测人员的比较请求被拒绝。切换任务提示新对话，刷新恢复保存历史，停止和超时有明确终态，其他登录看不到私人聊天。
9. 生成报告不依赖聊天或模型；重复生成不新增第二份当前报告。来源变化后更新原编号并解除旧确认，旧页面不能误确认更新后的内容；只有评测人员能确认。
10. 加载、空数据、读取失败和无权限均有明确反馈；桌面、窄屏和键盘能完成主要流程，主页素材失败时仍可静态浏览并进入产品。

具体实现与接口契约见[技术架构与 API 文档](架构与接口.md)和 [OpenAPI](openapi.yaml)；功能规格保留在 [specs](../specs/) 中。
