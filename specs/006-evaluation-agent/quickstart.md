# 评测助手运行与手工验收

## 本机开始

1. `.env.local` 使用开发 PostgreSQL、Auth.js 和访问密码；再按 `.env.example` 设置 `OPENAI_API_KEY`、`OPENAI_MODEL`、`ASSISTANT_BUDGET_USD`。密钥不发聊天、不提交 Git。
2. 本机 Node 直连模型超时且本机有代理时，设置 `OPENAI_PROXY_URL`。这是模型专用设置，不改变 Neon 连接。API 额度与 ChatGPT 会员分开。
3. 新环境安装依赖、生成 Prisma Client，核对目标后应用迁移。此次开发库已应用助手迁移及 `20261003100000_single_system_report`，无需 Seed 或重置。
4. `npm run dev`，退出旧会话，重新输入密码进入工作台。右下角出现 Q 版助手。
5. 在成功评测的结果／比较／异常页，点小人并选择“分析本页”。创建对话不调用模型，发送问题才调用。

系统报告使用另一条入口：侧栏“报告” → 选择成功任务 → 点击“生成评测报告”。不需要先打开助手、发送问题或准备聊天记录，报告生成和更新均不消耗模型额度。每个任务只显示一份当前报告；已有报告的数据未变化时复用，来源变化时点击“更新当前报告”，沿用原 ID 并恢复待确认状态。

## 手工体验清单

| 操作 | 应看到什么 |
|---|---|
| 问“概括当前任务最值得关注的指标” | 实际查询、逐步文字、引用与原始证据卡 |
| 比较页选好基线，问“哪些指标回退？查一下相关异常” | 按问题选择比较、列表或详情；不编造真实根因 |
| 无基线时问“提升多少” | 说明缺少基线，不捏造差值 |
| 追问、切页、收起再展开 | 保留聊天；对象变化时提示新建，不替换旧对象 |
| 刷新并打开历史 | 本次登录已保存内容仍在；不自动重跑未完成轮次 |
| 另一浏览器以同角色登录 | 看不到前一浏览器的聊天，业务任务仍共享 |
| 停止生成、快速重复发送 | 停止后不显示成功，阻止单次登录多轮并发 |
| 未开启聊天，直接在报告页生成 | 得到当前任务指标、人工复核结论和限制的系统报告；不调用模型 |
| 两个页面对同一任务点击生成，来源不变 | 仍是一份报告，ID、正文及已有确认状态保持不变 |
| 换评测人员查看同一报告并确认 | 可确认；工程师不能确认，服务端也检查 |
| 修改样本结论／草稿，再查看／确认 | 标记过时，拒绝确认；更新原报告后 ID 不变、旧确认清空，可重新核对确认 |
| 他人在另一页面更新报告，本页仍尝试确认 | VERSION_CONFLICT，读取更新后的报告并核对后才能确认 |
| 旧 `/overview` 地址带有效任务编号／无编号 | 分别跳到对应评测结果／任务列表；不再显示独立总览 |
| 未登录直访、传别人的会话／样本 ID | 401、404 或权限拒绝 |
| 窄屏、键盘、Escape、减少动态效果 | 输入可用、焦点返回小人、降低动画 |

这些页面场景待负责人操作，不以编译成功代替验收。指派、重开仍不开放。

## 维护与错误

- 名字、欢迎语、示例问题：`src/features/assistant/content.ts`；起伏／快慢：`appearance.ts`；窗口：`assistant.module.css`。
- 分析规则：`src/server/agent/agent.ts` 的 systemPrompt；工具字段：`tools.ts`。
- 次数、上下文、超时：`config.ts`。增大前同时复核费用预留；不是越大越好。
- 401：旧登录缺访问标识或登录过期，重新登录。
- MODEL_ERROR：到 Vercel Logs 展开对应消息 POST 请求，再查看 `assistant_run_failed`。HTTP 200 可能只是流启动，不代表问答成功。新诊断记录 `status`、`errorClass`、`providerCode` 等安全分类：401 先核对生产密钥；429 结合供应商错误码区分额度不足和限流；400 核对参数；无状态时查看网络错误码。旧版本可能只有 `name: Error`，需先发布诊断代码再定位；不能只凭通用提示判断余额。用量不明时保留预算预留。
- SOURCE_CHANGED：报告依据已变化，更新当前报告后重新核对并确认；不要求重新聊天。
- VERSION_CONFLICT：报告已被他人更新，先读取当前报告并核对，不能沿用旧页面的确认请求。
- BUDGET_EXHAUSTED：累计账本不足下一轮预留；不删除账本来伪造用量。本次开发与生产验证合计上限 $3，已有用量和预留金额仍计入。
- 超时／中止不自动重试，重新发送会开始新聊天轮次。聊天历史只属于当前有效登录，重新登录不恢复旧私聊；系统报告按任务共享，不读取聊天内容。

## 现有生产环境更新

1. 先确认 Vercel Production 指向的生产数据库。在本机被 Git 忽略的 `.env.production.local` 中同时配置 `DATABASE_URL`（连接池）和 `DIRECT_URL`（直连），二者必须来自同一分支／数据库。Neon 提供 `DATABASE_URL_UNPOOLED` 时，将该地址填入本机文件的 `DIRECT_URL`。任何一项缺失都应停止，避免 Prisma 从 `.env.local` 补入开发连接；不要展示或提交真实连接与密钥。
2. 备份并核对业务数据后，只应用新增迁移，不执行 Seed、恢复或重置。在仓库根目录的专用 PowerShell 中先清除当前进程的同名数据库变量，防止其覆盖正式文件，再显式指定 Prisma 7 配置：

   ```powershell
   Remove-Item Env:DATABASE_URL,Env:DIRECT_URL,Env:DATABASE_URL_UNPOOLED -ErrorAction SilentlyContinue
   node --env-file=.env.production.local node_modules/prisma/build/index.js migrate deploy --config=prisma7.config.ts
   ```

   清除只影响当前终端，不改配置文件。迁移后再次核对业务内容和报告 ID；数据库迁移本身不需要重新构建应用。
3. 在 Vercel 的 Production 设置 `OPENAI_API_KEY`、`OPENAI_MODEL=gpt-5.4-mini`、`ASSISTANT_BUDGET_USD=3`，密钥只核对已配置。不要设置本机 localhost 代理；代码在 Vercel 上会忽略 `OPENAI_PROXY_URL`。变量修改后 Redeploy 最新代码，等待状态 Ready，才会由新部署使用新值。
4. 先做不调用模型的检查：重新登录，查看成功任务和助手历史，打开助手并创建对话；发送问题才调用模型。报告页独立生成／更新系统报告也不调用模型。
5. 再按已授权的累计预算做真实问答，核对实际查询、文字流、引用、保存和刷新历史。一次发送可能经过多次模型请求，不应将一轮问答记成一次模型调用。消息接口声明 `maxDuration=90`，应用内部一轮 60 秒，仍须核对平台实际限制；登录隔离、报告和移动端也需人工验收。
