# Feature Specification: 演示工作台基础

**Feature directory**: `specs/001-demo-foundation`  
**Created**: 2026-09-23  
**Status**: Local stage 2 delivery accepted by the project owner; remaining evidence is listed in tasks.md  
**Input**: 阶段 2 工程基础；让面试官便捷进入真实会话，看到持久化、可重复的合成故事及清晰的工作台入口。

## User Scenarios & Testing

### User Story 1 - 快速进入演示工作台（Priority: P1）

首次访问的面试官可以通过清楚的演示入口进入工作台，在一个页面内理解 SimEval 的定位、当前合成项目、数据质量警告及已有评测状态。页面明确指出哪些功能尚未开放，避免将设计稿误认为已实现功能。

**Why this priority**: 这是有限面试时间内建立产品理解和信任的第一个接触点。

**Independent Test**: 在全新浏览器访问入口，完成便捷演示登录后查看概览；刷新页面，项目与状态保持一致，所有展示值可追溯到演示数据。

**Acceptance Scenarios**:

1. **Given** 全新浏览器尚无会话，**When** 访问工作台，**Then** 先看到 SimEval 用途、合成数据标识和便捷演示入口，不会直接看到受保护的数据。
2. **Given** 用户选择进入演示，**When** 进入工作台，**Then** 看到项目名称、数据集质量状态、至少一条已有评测及明确的下一步；无需手输演示密码。
3. **Given** 概览已经显示，**When** 刷新或重新打开页面，**Then** 相同的演示记录和状态仍可查看。
4. **Given** 某模块尚未实现，**When** 用户查看导航，**Then** 不会被带到假装可用的空白业务页面。

---

### User Story 2 - 角色与访问状态清楚可见（Priority: P2）

演示账号进入后可以看到当前身份和角色。未经登录的访问被拒绝；不同演示角色的权限由服务端决定。浏览器中的角色标识只是反馈，不构成权限来源。

**Why this priority**: 后续复核与报告确认依赖真实权限边界，面试演示也需要解释跨角色交接。

**Independent Test**: 分别以两个演示角色进入，核对身份标识；直接访问受保护地址及退出后重访均按会话状态处理。

**Acceptance Scenarios**:

1. **Given** 没有有效会话，**When** 直接打开受保护的工作台地址，**Then** 被引导到演示入口。
2. **Given** 已登录演示账号，**When** 打开工作台，**Then** 页面显示服务端确认的角色及账号，不允许仅修改浏览器状态来改变权限。
3. **Given** 会话失效或退出，**When** 刷新受保护页面，**Then** 不继续显示受保护的业务数据。

---

### User Story 3 - 固定故事可以重复核验（Priority: P3）

项目维护者可以重新准备演示数据，确保每次面试从同一个合成故事开始。预置的已完成故事供快速浏览；写入流程后续使用独立任务，不覆盖导览记录。

**Why this priority**: 同一故事才能稳定展示产品判断，也使后续功能测试和最终汇报可复现。

**Independent Test**: 连续两次重置演示数据，每次重新进入工作台，项目、质量警告、模型版本和准备好的评测及样本引用保持一致。

**Acceptance Scenarios**:

1. **Given** 新环境尚无演示数据，**When** 执行准备流程，**Then** 生成固定项目、角色、模型与数据集版本、质量警告、基线和候选评测，以及有来源的异常样本与报告记录。
2. **Given** 演示数据已存在，**When** 再次运行准备流程，**Then** 不产生重复的演示实体，关键标识和计数保持稳定。
3. **Given** 面试导览使用已完成故事，**When** 后续功能创建新的评测，**Then** 预置导览故事不被修改或覆盖。

### Edge Cases

- 演示数据未准备好：页面给出可理解的空状态，不显示伪造的统计值。
- 数据读取失败：页面显示错误与重试入口，不能将失败解释为“零条记录”。
- 会话失效：访问受保护内容时回到演示入口，避免只靠客户端隐藏内容。
- 窄屏与键盘：375px 宽度下无整页横向溢出，主要入口、退出和导航可用键盘到达。
- 多次点击演示入口：不会生成多个身份或重复导览数据。

## Requirements

### Functional Requirements

- **FR-001**: 系统必须提供首次访问即可理解产品用途的入口，并明确标注所有业务数据是合成演示数据。
- **FR-002**: 面试官必须能在不手输演示密码的情况下进入受控的演示会话。
- **FR-003**: 受保护的工作台内容必须要求有效服务端会话，并展示服务端确认的账号和角色。
- **FR-004**: 概览必须从已保存的演示记录展示项目、数据集质量状态、已有评测状态和下一步入口；不得把页面常量冒充已保存的业务数据。
- **FR-005**: 尚未实现的业务模块不得展示成可点击且看似可用的功能。
- **FR-006**: 演示入口和概览必须覆盖加载、空数据、错误、无权限与成功状态。
- **FR-007**: 演示数据必须稳定可重复准备，并能区分预置的只读导览故事与后续写入体验产生的记录。
- **FR-008**: 预置故事必须包含同一项目下兼容的数据集、模型、基准与评测版本，以及可追溯的质量、指标、样本、回补与报告引用；未实现的业务详情页面无需在本切片开放。
- **FR-009**: 退出或会话过期后，受保护页面不得继续显示业务数据。
- **FR-010**: 页面必须清楚区分当前已实现的概览能力与后续阶段计划中的质量、评测、对比、复核和报告动作。
- **FR-011**: 所有角色相关判断必须以服务端身份为准，浏览器中的显示标签不能改变权限。

### Key Entities

- **演示账号与角色**：识别演示会话的操作者及 ENGINEER、REVIEWER、ADMIN 角色；访问规则以服务端身份为准。
- **项目与不可变版本**：演示项目关联模型版本、数据集版本和 Benchmark。
- **演示证据链**：质量检查、评测任务、指标结果、异常样本、复核历史、回补任务与报告记录共同解释固定故事。
- **会话**：决定当前访问是否有效、由谁访问，不由页面标签决定。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 全新浏览器从入口到可读概览不超过两次明确操作；三分钟内可理解项目定位与当前演示故事。这是验收目标，部署后实测。
- **SC-002**: 测试矩阵中的所有无会话直接访问和退出后重访均无法读取受保护概览。
- **SC-003**: 连续两次准备演示数据后，固定项目、版本、质量状态、评测和样本引用的数量与标识一致，没有重复实体。
- **SC-004**: 在桌面与 375px 宽度浏览器中，入口和概览无整页横向溢出；主要操作可通过键盘完成。
- **SC-005**: 每个对用户可见的数字和状态都能在保存的演示记录中找到对应来源；读取失败时不显示零值替代。

## Assumptions

- 本切片交付可运行的入口、会话、概览和可重复演示数据；质量详情、创建评测、指标对比、异常复核及报告动作属于后续切片。
- 演示环境只保存明确标注的合成数据，不处理真实机器人轨迹或真实用户资料。
- 预置完整故事供快速浏览；完整写入流程以独立任务和后续功能验收。
- 具体演示账号登录方式、持久化结构和视觉实现由实施计划确定，不能削弱服务端权限校验。
