## 前置条件

1. Node.js 22、npm；项目安装依赖后使用锁文件复现版本。
2. 仅在本地被忽略的环境文件中配置项目专用 MySQL 连接、`AUTH_SECRET` 和演示登录所需的服务端变量。不要把真实值写进 Git、日志、截图或问题描述。
3. 核对 `DATABASE_URL` 指向专用开发或测试库。执行迁移前先查看目标数据库名称；不得对已有业务库运行 reset。

## 从零复现时的完整验证顺序

以下是已有本地项目库后的阶段验收命令，**不是每天打开项目都要重跑**。全新电脑先按 [README 的本地运行说明](../../README.md#本地运行与当前验收)用初始化脚本创建库、账号与环境文件；已有数据库与依赖时，日常只需在项目根目录运行 `npm run dev`。重装依赖前先停止正在运行的开发服务器。

从 `simeval-app/` 执行：

```powershell
npm ci
npm run db:deploy
npm run db:seed
npm run db:seed
npm run lint
npm run typecheck
npm run test:unit
npm run build
```

重复 Seed 的第二次执行应保持固定项目、模型、数据集、评测、样本和报告的标识与数量，不新增副本。只应用现有迁移用 `db:deploy`；修改 Schema 并开发新迁移才用 `db:migrate`，后者需要 shadow database 权限。数据库集成测试须使用独立测试库；首次运行 `.\scripts\setup-local-db.ps1 -Database test` 准备环境，然后显式运行 `npm run test:integration`。网页验收在启动应用后由项目负责人按下方步骤亲自操作；详细命令见 [README](../../README.md#本地运行与当前验收)。

本机执行记录（2026-09-24）：`202609240001_demo_foundation` 已应用；两次 Seed 都报告 1 个项目、2 条预置评测和 2 条异常样本。复核数据库包含 3 个演示用户、4 条质量检查、8 条指标结果、2 条复核、1 条回补、1 份报告和 4 条审计。lint、类型检查、13 项单元／组件测试、1 项独立数据库集成测试及生产构建通过。此前执行的自动浏览器测试已按项目负责人决定移除；网页体验以后按下方清单手工验收。用 `npm run start` 做本地生产预览时，Auth.js 需要在**仅用于可信 localhost 的** `.env.local` 设置 `AUTH_TRUST_HOST="true"`；部署环境另按托管平台的可信 Host 配置处理。

## 基础浏览器走查

1. 全新浏览器进入首页：看见产品一句话、合成数据标识和便捷演示入口。
2. 点击“进入演示”：建立实际服务端会话，不要求手输密码；进入概览看到项目、WARNING、已完成评测与角色。
3. 刷新概览：记录与状态不变。退出后直接访问概览：被引导回入口，不能读到受保护数据。
4. 空／错误已有组件测试；需要真实浏览器故障验证时，另用隔离实例与专用空库／故障配置，不改演示开发库。前者应显示空状态，后者应显示错误和重试。
5. 在桌面和 375px 宽度检查整页无横向溢出、主要操作可见、键盘 Tab 与 Enter 可到达并触发入口及退出。
6. 核对导航：未实现的质量详情、评测创建、对比、复核和报告不表现为已可用页面。
