# 实施方案

- `src/app/page.tsx`：公开页面组合，保留原入口错误提示。
- `src/features/home/content.ts`：可编辑文案、外链、步骤；`portrait.hint` 统一维护手机和桌面的“上下左右移动鼠标探索”提示，无需接数据库。
- `home-page.tsx`、`home.module.css`：服务端排版，CSS Module 隔离工作区样式；仅互动已准备完成（`ready`）的人物区域设置 `touch-action: none`，区域外和静态浏览保留页面滚动和链接操作。
- `interactive-home.tsx`：React 生命周期、加载屏、触屏和键盘操作；以首个触点的 `pointerId` 和按下坐标管理单指拖动，使用 pointer capture 延续区域外移动，松手／取消／失焦释放并回待机；卸载清理输入状态。通过 children 保留正文服务端渲染。
- `avatar/controls.ts`：纯函数负责指针区域、滞回与逐帧运动；`touchTarget()` 将按下起点到当前位置的位移映射为方向和进度，`TOUCH_SETTINGS` 集中管理触控手感，通过增大拖动行程与其上下限降低触屏灵敏度，不调整播放速度。
- `avatar/engine.ts`：独立 Canvas 引擎，流式下载、解码验证、6 张 LRU 缓存、预解码、回程与清理；逐帧不触发 React 重渲染。
- `public/avatar/v1/`：仅复制已验收的 WebP 运行图集及清单，版本目录采用长期缓存。替换素材须换版本目录，避免旧 CDN 缓存。
- 维持现有 Next.js／React／TypeScript 与 CSS，无新增动画库、数据库表或 HTTP 业务接口。

先固定规格、文件职责和内容，再迁移动作引擎与高清资源，组合页面，最后依据浏览器实际画面与回程数据修正。素材哈希需与已认可 Demo 一致。

人物交互的当前验收方式以 [spec.md 的验证约定](spec.md#验证) 为准：保留手工步骤，删除相关自动化测试，不为调节交互参数新增测试。通用代码检查与业务功能测试仍由现有 CI 执行。

手机拖动复用现有动作目标与共同待机帧，不新增素材或引擎分支；保留全窗口鼠标、人物区键盘与减少动态效果模式，减少动态效果时触控直接显示目标姿势。静态浏览不接管触控。2026-10-04 本轮补触控输入、统一提示并降低触屏灵敏度，按负责人约定不运行测试或构建，实际手感及页面操作待手工体验。
