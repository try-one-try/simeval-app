# 实施计划

**新原型已认可，以下为待实施计划。** 复用模块化单体、认证、仓储、状态逻辑与已认可视觉；不增加队列、WebSocket 或自动浏览器测试框架。

## 1. 文件怎样串联

| 位置 | 改造职责 |
|---|---|
| `src/server/auth/`、工作台 layout | 两个预设会话、身份切换、角色默认入口与导航；权限仍在服务端 |
| `src/domain/evaluation.ts` | 自主配置／兼容性、可选基线、目标与状态规则 |
| `src/server/providers/` | 按配置和 Seed 产生确定性结果，摆脱必填基线 |
| `src/server/repositories/` | 目录查询、任务列表、条件更新、软删除、事务与审计 |
| `src/server/application/` | 组织目录／任务用例，输出安全 DTO |
| `src/server/http/`、`src/app/api/` | 统一校验／错误，实施目录和删除接口及创建契约修订 |
| `src/features/`、页面 | 两步创建、身份导航、任务选择与延续、状态／恢复；页面只组合 |
| `prisma/` | 兼容旧数据的追加迁移、目录与双身份 Seed；不 reset |

复核草稿／确认版本和报告输入版本先保持设计接口，在各自切片实施；不提前建立空模块。

## 2. 开工前固定四项

1. **目录矩阵**：可选版本、Benchmark 的指标／成功规则、兼容组合、Episode 范围和三种质量状态。
2. **结果算法**：推荐配置复现固定故事；其他配置按模型／场景／Seed 等确定性变化，不声称真实模型表现。
3. **任务容量**：是否限制进行中任务及具体数值；若限制，事务内校验、错误反馈和边界测试一起设计。未定前不把“3”写成已生效门禁。
4. **迁移方案**：名称／可选基线、目标／快照、软删除；兼容历史 ADMIN／分类／回补与旧报告，不破坏外键。新增字段见[架构](../../docs/architecture.md#4-数据变化待迁移)。

## 3. 写入边界

创建／重试复查目录与质量，并一起保存任务、配置、幂等与审计。同步／取消按允许状态更新；完成的指标／异常／终态／审计同事务。删除核对本人、终态和固定示例保护，写删除标记与审计；普通列表过滤，引用解析保留。

会话／数据库角色／Origin／Zod 不能依赖 UI。新创建请求的基线可空，旧接口改造完成并验证后再更新 implemented 标记。GET 不写库；外部 Provider 网络不进入数据库事务。

## 4. 推进顺序

1. **身份入口适配**：复用认证与工作台基础，接两身份会话／切换、角色导航／默认入口、未开放提示，验证后由负责人验收。
2. **自主创建**：固定四项决策，追加迁移／目录／规则，接两步配置与质量确认、仓储／应用／HTTP。
3. **独立执行**：无基线模拟、结果持久化、刷新恢复和幂等／并发保护。
4. **任务管理**：多任务选择／延续、所选任务总览、取消／重试／软删除与引用保护。
5. **新版验收**：各批相关单元／隔离集成、lint／类型／构建与手工网页走查；回写实际结果，全部通过再进入后续功能。

一轮可完成多个相连步骤，不为低风险文案逐次签收；行为、权限、数据变化必须有证据。
