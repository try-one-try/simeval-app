# 实施计划

**新原型已认可，阶段 3 已签收，阶段 4 已按本计划实施，等待负责人验收。** 复用模块化单体、认证、仓储、状态逻辑与已认可视觉；不增加队列、WebSocket 或自动浏览器测试框架。

## 1. 文件怎样串联

| 位置 | 改造职责 |
|---|---|
| `src/server/auth/`、工作台 layout | 两个预设会话、身份切换、角色默认入口与导航；权限仍在服务端 |

| `src/server/repositories/` | 目录查询、任务列表、条件更新、软删除、事务与审计 |

| `src/server/http/`、`src/app/api/` | 统一校验／错误，实施目录和删除接口及创建契约修订 |

复核草稿／确认版本和报告输入版本先保持设计接口，在各自切片实施；不提前建立空模块。

2026-10-04 列表读取收敛：仓储用专用 `select` 读取任务摘要，通过过滤 `_count` 统计未解决或有非空草稿的异常；应用层输出 `RunSummaryData`。任务选择首屏、翻页和助手选择同步使用摘要，不再加载指标、配置快照和草稿正文；详情与创建／取消／重试继续使用完整任务 DTO。HTTP 契约以 [OpenAPI](../../docs/openapi.yaml) 为准，本轮按负责人约定仅代码审查，未运行测试、构建或性能实测，未写数据库。

验收微调：工作台 layout 移除底部身份区，IdentitySwitcher 复用原退出 Server Action；CSS 用共同宽度变量同步侧栏与正文偏移，默认 280px、展开 352px，主导航文字 18px、总览 16px。任务选择页的首屏查询与客户端翻页共用 `src/lib/evaluation-dto.ts` 的每页 6 条常量，避免首屏与翻页数量不一致；HTTP 默认分页保持原契约。

## 2. 已固定的实施规则（2026-09-27）

- **目录**：v2.4／v2.5 可测，v2.1／v2.2／v2.3 作为历史合成基线；三个数据集展示 PASSED／WARNING／FAILED。仓储综合基准支持全部目录数据，遮挡基准只支持含遮挡的数据；质量失败仍禁止执行。兼容规则统一在 `src/domain/evaluation-catalog.ts`。
- **命名**：英文模型／数据集、固定任务与演示填入名称统一在 `src/domain/evaluation-catalog.ts`；Seed、目录增量和表单复用。已有开发库仅增量改名并写审计，保留 ID、模型版本、指标、复核与引用，不重跑完整 Seed。
- **口径**：综合基准 50–1000 Episodes，遮挡基准 50–500，且不超过数据集上限；默认推荐 200、Seed 20260901。成功规则由 Benchmark 定义；可选达标目标为 80%／85%，与历史比较基线是两件事。
- **模拟**：保存 `mock-v2` 参数快照，按模型参数、数据／基准难度、Episode 与 Seed 生成确定性指标；演示推荐配置复现 81% 成功率与 13% 遮挡碰撞率。无需基线即可执行；这些数值不代表真实模型性能。
- **容量**：每位工程师最多 3 个 QUEUED／RUNNING 任务。创建／重试先锁账号行，再查幂等与容量；重复提交不占新名额，取消／终态释放名额。
- **任务防重名（2026-10-05）**：同项目未软删除任务名，新旧名称都 trim 后转小写判重，包含固定示例和其他创建者。仓储仅查询名称列，领域层负责判重和“原名 · 重试 N”命名；从 1 起选未占用编号，截短原名使总长不超过 120 字。重名为 `409 RUN_NAME_CONFLICT` 与 `fieldErrors.name`，创建页保留输入并回到名称编辑。相同幂等请求先返回原任务，重试请求摘要不包含动态编号。本次不增加 Schema 或迁移，不自动改历史名称。
- **迁移**：仅追加可空目标、配置快照、删除时间／操作者和索引。历史任务无需回填才能读取；旧任务执行时从已有配置构造快照。软删除不删结果、基线与报告引用。新增目录用 `db:catalog` 增量写入，不重置开发库故事。

## 3. 写入边界

演示集由 `prisma/demo-fixtures.ts` 增量维护，`seedCatalog` 在补目录后调用；完整 Seed 与 `db:catalog` 共用。新任务采用稳定 ID，已有同名同配置记录沿用原 ID 并标记固定示例；只补缺失任务，保留人工编辑和软删除。模拟指标计算提取到 `src/domain/simulation-results.ts`，Provider 与 Seed 共用；已有模拟算法不变。

创建／重试复查目录与质量，并一起保存任务、配置、幂等与审计。同步／取消按允许状态更新；完成的指标／异常／终态／审计同事务。删除核对本人、终态和固定示例保护，写删除标记与审计；普通列表过滤，引用解析保留。

创建／重试沿用现有 Serializable 事务，账号行锁保护进行中容量，新增项目行锁保护同项目名称分配。幂等重放先返回原任务；只有实际新建时才在项目锁内读取未软删除名称、判重或选重试编号并保存，防止不同账号并发创建同名任务。

会话／数据库角色／Origin／Zod 不能依赖 UI。新创建请求的基线可空，旧接口改造完成并验证后再更新 implemented 标记。GET 不写库；外部 Provider 网络不进入数据库事务。

## 4. 推进顺序

1. **身份入口适配**：复用认证与工作台基础，接两身份会话／切换、角色导航／默认入口、未开放提示，验证后由负责人验收。
2. **自主创建**：固定四项决策，追加迁移／目录／规则，接两步配置与质量确认、仓储／应用／HTTP。
3. **独立执行**：无基线模拟、结果持久化、刷新恢复和幂等／并发保护。
4. **任务管理**：多任务选择／延续、所选任务总览、取消／重试／软删除与引用保护。
5. **新版验收**：各批相关单元／隔离集成、lint／类型／构建与手工网页走查；回写实际结果，全部通过再进入后续功能。

一轮可完成多个相连步骤，不为低风险文案逐次签收；行为、权限、数据变化必须有证据。
