# 数据质量与模拟评测规格

**状态：2026-09-27 新产品原型已认可，规格已修订，新版工程已接通，等待负责人手工验收。** 第一版技术证据保留在[任务](tasks.md)，不视为新需求通过。设计基准：[Figma](https://www.figma.com/design/Y2ZIhN1yuuXBeieGkxtnsH/simeval?node-id=43-2)。

## 1. 用户与范围

一个 ENGINEER、一个 REVIEWER 演示账号，无注册。工程师默认进入创建，评测人员默认进入异常复核的任务选择；登录选择和登录后的身份切换均清楚可见，切换建立真实会话。

工作台底部不重复显示姓名／身份或退出区；退出入口收在右上角身份弹层内。桌面文字侧栏默认 280px、展开 352px，主导航文字 18px、总览 16px；正文预留默认宽度，展开不推动正文；窄屏继续使用菜单。

| 身份 | 导航与权限 |
|---|---|
| ENGINEER | 创建评测、评测任务、模型对比、异常复核、报告、下方总览；创建／管理本人任务、编辑复核草稿、生成／阅读报告草稿 |
| REVIEWER | 异常复核、报告、评测任务、下方总览；共享读取、编辑／确认最终结论和报告；不能创建、取消、重试或删除任务 |

本功能分批交付：先完成身份入口／角色导航适配，再完成自主配置、质量、执行、多任务上下文、取消／重试／软删除；比较／复核的完整业务在后续切片，报告在更后面的切片。前一批通过相关验证和负责人验收，再推进后一批；未开放动作明确提示，不提供虚假成功。

### 身份入口这一批的验收

- `/login` 使用原生单选组选择 ENGINEER／REVIEWER，无注册；未选项不能依靠改角色标签获得权限。
- 登录和切换由 Server Action 执行，Zod 验证身份；Credentials 只接受对应预设 email、isDemo 和数据库角色，口令只从服务端环境读取。
- 工程师默认 `/evaluations/new`，评测人员默认 `/anomalies`；未登录回 `/login`。切换失败保留原会话并提供重试，成功替换真实会话和默认入口。
- 两身份按表中的顺序显示可点击文字导航，总览置底；比较／复核／报告暂展示未开放页。阶段 4 已替换为自主配置与质量两步，任务名称在首屏必填。
- 评测任务提供基础共享只读列表，能打开已有任务；完整多任务选择／延续、总览与删除留下一批。评测人员直访创建／对比显示无权限，写 HTTP 仍在服务端拒绝。
- 历史 ADMIN 记录保留，但不能建立或继续产品会话。检验双身份、非法选择、数据库角色不匹配、旧会话失效、刷新／退出、窄屏和键盘后，由负责人验收。

## 2. 创建与质量

1. 两步：配置 → 确认所选数据质量。任务名必填自由输入，1–120 字；选择模型版本、数据集版本、Benchmark，Episode 为整数，Seed 可在更多设置修改。
2. 默认不替用户选配置；“使用演示配置”只填表，仍可修改。目录展示版本、范围和兼容性，错误说明放在对应字段。
3. 历史比较基线可不选；有基线时要求成功、同项目／数据／Benchmark／Episode／Seed、不同模型版本。成功率目标可不设或选 80%／85%，与历史基线分开。
4. 质量来自数据库的预置报告，标注合成数据。PASSED 可创建；WARNING 明确接受；FAILED 阻断。换数据集清除旧确认，服务端再次校验。
5. 提交前不产生任务；提交后保存 QUEUED、创建者、实际配置／质量接受及审计，进入新任务详情。
6. 无基线也能产生确定性结果；模型／数据／Benchmark／Episode／Seed 必须影响结果口径。不能所有配置都显示同一故事。

## 3. 任务与导航

- 除创建外，从顶层导航进入先选任务；正文后续按钮直接携带当前 runId。详情持续显示名称／ID及更换入口。
- 各板块共用的任务选择页每页最多 6 条，显示总数、当前／总页数及上一页／下一页。翻页后清除旧选择；删除后重新查询，最后一页变空时回到上一页。此为页面展示设置，HTTP 默认分页不变。
- 等待／执行显示不确定进度条、已用时间和就近取消；自动同步，正常流程没有手动刷新按钮。同步失败停止动态提示并提供重新连接。完成后保留结果，工程师主按钮进入同任务的模型对比，评测人员进入异常复核。
- 多个任务独立保存状态和证据，刷新可恢复明确选定对象；不以最近任务覆盖选择。列表中区分预置示例和用户新任务。
- 系统提供的任务、模型与数据集名称采用专业英文；任务按场景＋用途＋版本命名，例如 `Warehouse Candidate v2.4`。模型为 `PickPlace Policy`，版本独立显示；一键演示任务名前缀为 `Custom`。自由输入规则不变。演示环境只保留覆盖核心功能的任务，控制在两页内，不截断真实用户列表。
- QUEUED → RUNNING → SUCCEEDED／FAILED；未结束可变 CANCELLED。GET 只读，POST sync 推进模拟，不运行真实仿真或后台 Worker，不编造进度。
- 结果、异常、终态和审计同事务保存；同任务重复／并发同步不能重复写。
- 仅本人排队／运行任务可确认取消；取消与完成冲突保留已完成结果。FAILED 重试另建 ID、关联原记录，重新检查配置与质量。
- 任务选择页提供“删除所选任务”；仅本人 SUCCEEDED／FAILED／CANCELLED 可软删除，进行中先取消，固定示例受保护。删除后普通列表不再出现，清除当前界面上下文，保留结果／基线／复核／报告／审计引用。重复删除返回同一删除结果。
- 创建和重试带幂等键；同用户／操作／键及内容返回原任务，同键不同内容返回 409。
- 无任务／读取失败／无权限／网络冲突分别展示；失败保留输入和当前对象，提供恢复动作。取消确认有取消入口、Escape 与焦点恢复。

原型用三条预置任务和一个新建槽位展示交互；删除只有按钮。真实容量和持久化属于工程，不能据此宣称已实现。

## 4. 后续切片的依赖

异常详情两种身份都有明显的编辑／修改入口，自由输入、保存／取消；工程师草稿不覆盖评测人员确认。删除人工分类与独立回补步骤。待复核以小范围红字注明“需评测人员复核”。

最终结论修改保留历史，expectedVersion 冲突保留草稿，并使旧报告过时；AI 输出只是有证据的草稿，评测人员才能确认。指派／重开在复核实施前另行细化，不作为当前主线的额外步骤。

## 5. 编码前需定与验收

### 核心演示集

新环境 Seed 提供 10 条英文命名的固定合成任务，两页 6＋4：候选／历史基线 4 条、部分复核 1 条、失败／重试 2 条、取消 1 条、质量通过且达标 1 条、遮挡专项未达标 1 条。后两条使用 v2.5，分别覆盖 PASSED 数据与不同 Benchmark／不兼容基线。质量 FAILED 在创建页展示阻断，不生成任务；运行中、草稿、取消、删除与权限通过实际操作验证，不为每个状态另建示例。

固定任务沿用示例保护；新增用户任务仍可按原规则管理。增量补示例时复用已有同名同配置演示记录，保留 ID、结果、结论、历史和删除状态；重复执行不重置或复制。所有新增成功示例复用正式模拟算法，不另写一套成绩。

兼容目录、mock-v2 结果算法、每位工程师最多三个活跃任务与追加迁移已在[计划](plan.md)固定并实现。

验收要求：两身份与服务端权限、自由配置／兼容性、三种质量门禁、首次无基线、多任务不混用、取消竞争、重试历史、软删除引用、刷新／窄屏／键盘；通过 lint、类型、相关单元／独立 MySQL 集成和构建，再由负责人手工验收。具体步骤见 [Quickstart](quickstart.md)。
