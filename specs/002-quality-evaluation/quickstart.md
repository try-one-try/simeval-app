# 数据质量与评测：运行和验收

**本轮阶段 3 已交付双身份入口，等待负责人验收。** 自主配置与完整任务管理属于阶段 4，当前创建仍沿用第一版。首次安装看 [README](../../README.md)；已有环境只需启动 MySQL，在仓库根目录运行：

~~~powershell
npm run dev
~~~

本轮未改 Schema、迁移或开发库 Seed，不需要重新初始化数据库。已有本项目服务时直接打开网页；看到旧页面先刷新。

## 1. 阶段 3：照着检查身份入口

1. 打开 `http://localhost:3000/login`。只有算法工程师、评测人员两个选项；圆点与文字粗细显示选择，没有“已选择”标签。
2. 选择算法工程师并进入。右上角显示算法工程师；默认是创建页。侧栏顺序为创建评测、评测任务、模型对比、异常复核、报告、总览。任务名称在表单最前面，默认空白，须填写 1–120 字；接受警告后，空白名称仍不能提交。自主配置和质量两步在阶段 4 接通。
3. 点右上角“切换”，选择评测人员，确认继续。身份应真的变更，默认进入异常复核；当前显示未开放提示。导航只保留异常复核、报告、评测任务、总览。
4. 刷新页面，身份和导航不变。打开“评测任务”，能看到共享记录，预置示例与新建模拟任务分别标注；当前只显示最近 20 条。打开一个已完成任务，评测人员看不到新建／取消／重试入口。
5. 仍以评测人员身份直接输入 `/evaluations/new`、`/comparisons`。应显示无权限，不展示创建表单；仅隐藏侧栏不能算通过。
6. 切回工程师，默认回创建页。依次点击比较、异常复核、报告：都有未开放说明和返回任务入口，不出现虚假结果。
7. 打开身份弹层后按 Escape。弹层关闭、焦点回到切换按钮。将浏览器缩到约 375px，检查登录／身份按钮／任务列表不横向溢出；菜单可点，Escape 关闭后焦点回菜单按钮。
8. 点“退出演示”，回到首页；再次直访 `/evaluations` 应回登录页。首页主按钮进入身份选择。

每项记录通过／不通过；有问题提供页面地址和现象。原基础验收保留，这批身份行为需重新签收。技术检查通过也不能代替负责人使用体验。

## 2. 当前旧评测仍能做什么

工程师创建页仍预填 v2.4、v2.3 基线、200 Episode 与 Seed；需接受 WARNING。同步约 2 秒运行、12 秒完成，保存指标和两条异常；取消与失败重试沿用旧规则。任务列表已能明确打开某条记录。

没有自主目录、首次无基线、跨板块任务上下文或删除写入；总览仍是固定故事。比较／复核／报告当前只是未开放页。不要把 Figma 交互当成数据库实现。

## 3. 阶段 4 实现后再验

| 场景 | 应看到什么 |
|---|---|
| 自主创建 | 自由填任务名，选模型／数据／Benchmark；演示配置可修改，不兼容有原因 |
| 质量 | PASSED 可继续，WARNING 须接受，FAILED 阻断；换数据重置确认 |
| 首次无基线 | 可以完成模拟；有基线才显示比较 |
| 多任务 | 各板块先选任务；后续按钮直接延续，刷新和切换不混用 |
| 取消／重试 | 本人未结束任务可取消；完成竞争保护结果；失败重试新 ID，保留原记录 |
| 删除 | 本人终态任务确认软删除；运行中先取消；固定示例保护，引用和审计保留 |
| 错误／权限 | 评测人员不能管理任务，伪造请求仍拒绝；错误保留输入，冲突显示最新状态 |

容量、兼容矩阵、模拟算法与迁移先定稿；不靠清空开发库制造异常。
