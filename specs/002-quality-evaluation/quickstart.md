# 数据质量与评测：运行和验收

**当前代码仍是第一版；新版原型的以下目标尚不能全部在网页操作。** 新环境按 [README](../../README.md) 初始化，已有环境在仓库根目录运行：

~~~powershell
npm run db:generate
npm run db:deploy
npm run dev
~~~

先停止旧开发服务再生成 Client／重启；不为文档修改重做 Seed。已有环境的三个评测字段已追加迁移；新设计迁移尚未生成。

## 1. 现在能检查什么

1. 登录默认工程师，质量页显示 2,400 合成统计、四项预置检查和 18 条警告。
2. 创建页预填 v2.4、v2.3 基线、200 Episode 与 Seed；确认警告后创建独立任务。
3. 同步约 2 秒运行、12 秒完成，保存指标和两条 OPEN 异常；刷新仍可读。
4. 旧导航会恢复最近非固定任务，“新建评测”再进表单；这不是新版的先选任务设计。
5. 新任务可确认取消；故障演示可 FAILED → 新 ID 重试，原记录保留。
6. 检查 375px 无横向溢出、Tab 焦点、菜单／弹层 Escape 和焦点恢复。

当前没有双身份选择、自主目录、无基线执行或删除按钮的真实写入；复核／报告后续开放。不要把 Figma 成功提示当作数据库证据。

## 2. 新版工程完成后怎样验收

| 场景 | 应看到什么 |
|---|---|
| 身份 | 登录二选一、选项清楚；工程师进入创建，评测人员进入异常任务选择，切换更新真实会话和导航 |
| 自主创建 | 任务名自由输入，版本／数据／Benchmark 可选；演示配置可修改，不兼容有原因 |
| 质量 | PASSED 可继续，WARNING 须接受，FAILED 阻断；换数据重置确认 |
| 首次无基线 | 可创建并完成，结果注明模拟；有基线才显示比较 |
| 多任务 | 创建两个不同任务，各板块先选择；正文后续直接进入同任务，刷新和切换不混用 |
| 取消／重试 | 本人未结束任务可确认取消；完成竞争保护结果；失败重试新 ID，原失败保留 |
| 删除 | 本人终态任务可确认软删除，列表消失；进行中要求先取消；固定示例保护，引用和审计保留 |
| 错误／权限 | 评测人员不能管理任务，伪造请求仍拒绝；网络错误保留输入，冲突显示最新状态 |
| 视觉／键盘 | 保留认可的黑白风格、文字侧栏；窄屏可点击，焦点和弹层关闭正常 |

默认演示库不靠删表制造异常；质量阻断、非法权限、幂等、取消竞争及软删除引用用单元／独立集成测试补充。

## 3. 工程检查

~~~powershell
npm run lint
npm run typecheck
npm run test:unit
npm run test:integration
npm run build
~~~

集成测试只使用独立 simeval_test，迁移／重复 Seed／事务和并发按新规则验证。网页由负责人手工验收，不增加自动浏览器测试框架。记录“通过／不通过”和必要截图；全部通过后才能进入下一阶段。
