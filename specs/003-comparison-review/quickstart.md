# 阶段 5 验收

**阶段 5 已提交，本轮补充核心演示任务与同任务双向导航。** 用下面步骤核对功能。基础运行看 [README](../../README.md)。

## 1. 先启动

在 simeval-app 中，先在原开发终端按 Ctrl+C，再运行：

~~~powershell
npm run dev
~~~

看到 Ready 后打开 http://localhost:3000/login。本机已生成 Prisma Client、应用新迁移，不需要重新初始化或重跑完整 Seed。其他电脑拉取后有新迁移时先运行 db:generate、db:deploy；运行 db:catalog 补缺失核心示例，再启动；新环境按 README 初始化。

## 2. 先验主线

1. 登录算法工程师，侧栏点“模型对比”，单选 **Warehouse Candidate v2.4** 并进入。
2. 看两项关键指标：成功率 76%→81%、遮挡碰撞率 8%→13%，都是 +5 pp，分别改善／回退。展开完整指标，核对方向和 200／50 样本数。
3. 从碰撞指标点“关联证据”，再进 sample_017。任务名称／ID、场景和指标应保持一致；返回异常列表／模型对比不应重新选任务。
4. 用侧栏换到预置的 **Warehouse Evidence Review v2.4**。这是无基线成功任务；比较默认只显示本次结果，也可补选同口径 v2.1／v2.2／v2.3。选择框有浅底边框；切换历史版本后指标随所选记录变化，不重算任务。
5. 打开 sample_018，点“编辑／修改结论”与“填入演示结论”，按需修改依据和处理建议，保存草稿后刷新。草稿应保留，最终结论仍未确认；工程师不能最终确认。
6. 右上角切评测人员，进入异常复核，选择同一任务／sample_018。编辑入口应明显，可以确认草稿；确认后显示最终文字、确认人／时间，草稿清除、待复核数减少。
7. 再修改最终文字，展开历史。旧文字与操作者应保留，确认修订号递增；工程师再次查看能看到最新最终内容。
8. 点“查看本次报告”：直接带当前任务进入，说明生成／确认暂未开放。此阶段只标记已有报告过时，不自动生成或更新报告。

固定故事保留旧复核／回补原文，不代表当前有回补功能。可在复核示例上体验编辑；需要可删除或重复练习的记录时，另建任务。

## 3. 再验两个关键状态

| 检查 | 怎样做 | 正确结果 |
|---|---|---|
| 等待与下一步 | 创建一个明确命名的测试任务；等待时查看细进度条、计时与旁边取消，取消需确认；另一个任务等待完成 | 首屏自动同步，无刷新按钮；计时不是完成百分比。完成页主按钮直达同任务模型对比，评测人员直达异常复核；不用重新选任务 |
| 示例填入 | 编辑结论后填入示例，再修改或取消 | 只改变输入；保存／确认前不写库，取消不改变已有结论 |
| 同任务前进／返回 | 比较选 v2.1，标题上方返回结果，再进入比较；从碰撞指标进入证据、样本详情与报告入口，再返回 | 无需重选任务；v2.1 或“不对比”选择保留，样本／报告返回保留异常筛选。返回为白底次级按钮，下一步为黑色主按钮；评测人员从异常页返回结果，跳过对比 |
| 导航与任务分页 | 侧栏进入评测任务；列表超过 6 条时选择任务，再点下一页，检查末页；打开删除确认后按 Escape | 主导航 18px、总览 16px；每页最多 6 条，显示当前／总页数；翻页清除旧选择，首末页按钮正确禁用，关闭确认不删除 |
| 并发冲突 | 评测人员在两个窗口打开同一样本并编辑；先保存第一个，再存第二个 | 第二个冲突，输入保留；读取最新记录后人工核对，再保存或取消 |
| 窄屏与键盘 | 浏览器调 375px；打开编辑，使用 Tab／Shift+Tab／Escape | 页面无横向溢出，弹层可滚动；焦点留在弹层，Escape 回编辑入口 |
| 不同配置与目标 | 分别打开 Warehouse Clean Evaluation v2.5、Occlusion Stress Evaluation v2.5 | 前者 PASSED 数据、87% 达到 85% 目标；后者遮挡专项、78% 未达标。两者没有兼容历史基线，只显示本次结果；遮挡专项碰撞指标基于全部 200 Episode |

其他已验证：无基线、筛选、空证据、错误父任务、角色拒绝、上下文延续与刷新。可任选核对；故障状态完整走查与新电脑初始化集中后续质量阶段。
